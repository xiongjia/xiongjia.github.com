# part-0001 摘要与引言：范式重构的宣告

- **输入来源**: 本地 pdf 预提取文本（source-01.txt，arXiv:2606.05608v1 [cs.SE]）
- **原文链接**: <https://arxiv.org/html/2606.05608v1>

## 摘要

封面信息：作者 Zhenfeng Cao（Lingxi Intelligent Investment (Shenzhen) Development Co.,
Ltd.），正文标注日期 2026-06-05。

**Abstract** 浓缩全文立场：半个多世纪以来软件工程建立在「人分解问题 → 把决策逻辑编码成
静态代码 → 随需求演化手工维护」的前提上。论文论证：AI agents（LLM 作主要推理引擎、
动态生成并丢弃代码作为工具性资源）构成的是软件范式的**根本重构**而非增量改进。方法上做
复杂度缩放的第一性原理分析，形式化区分「代码承载决策逻辑」的传统软件与「代码只是推理
循环的临时工具」的 agentic 系统；历史线上梳理 licensed software → SaaS → 作者所称
Agent-as-a-Service（AaaS），指出每次转移都把更多复杂度移离终端用户；提出 Agentic
Engineering 作为新兴学科（研究对象、控制模型、人的角色均与软件工程不同）；并以
SWE-bench Verified、EvoClaw、LangChain 多智能体协同研究等实证同时展示潜力与当前局限；
收尾给出走向 self-evolving agent 生态系统的四阶段路线图与给实践者的具体建议。

**§1 Introduction（前段）** 交代学科原点：软件工程在 1968 年 NATO Conference 上诞生于
一场危机——系统复杂度超过了 ad-hoc 编程实践能管理的程度；奠基洞见是「严格的方法论——
结构化设计、模块化分解、配置管理、系统化测试——能驯服复杂度」。半个世纪大体有效：
waterfall → agile、monolith → microservices、手工部署 → CI/CD。

## 要点归纳

- 论文给自己定的目标是「范式转移」论证，非「工具升级」论证——开篇即亮明立场
- 复杂度转移史观（谁承担复杂度、谁被解放）是后文三代交付史（§3）的分析框架雏形
- Abstract 即全文骨架：必要性论证 → 范式转移 → 新学科 → 实证校准 → 路线图

## 术语 / 概念

- **Agent-as-a-Service（AaaS）** — 论文自定义的第三代软件交付形态：agent 在云端自主
  理解 / 构建 / 运行，复杂度由 agent 承担，按 outcome 计费
- **first-principles analysis（第一性原理分析）** — 论文的论证方法：从复杂度缩放定律
  出发推导 agentic 范式的必然性，而非从市场观察出发
- **essential complexity（本质复杂度）** — 后文将借 Brooks 的概念展开论证（见 part-0002）

## 原句摘录

> Software engineering, as codified at the 1968 NATO Conference, was born from a crisis:
> systems were growing in complexity beyond what ad-hoc programming practices could
> manage. … For five decades, this bet largely paid off.

> This paper argues that the emergence of AI agents … constitutes not an incremental
> improvement but a fundamental restructuring of the software paradigm.
