# part-0008 组织建议、结论与参考文献

- **输入来源**: 本地 pdf 预提取文本（source-08.txt，arXiv:2606.05608v1 [cs.SE]）
- **原文链接**: <https://arxiv.org/html/2606.05608v1>

## 摘要

**§7.3 给组织（现在就应开始准备 agentic 转型）**：

1. **识别 agent-ready 工作流**——并非所有软件工作同样适合 agent 自动化：成功判据清晰、
   范围明确、已有测试基础设施的任务是理想起点
1. **投资 evaluation frameworks**——agent 输出质量关键取决于评估信号质量；测试套件要
   超越「正确性」，测量 robustness、maintainability 与对业务意图的对齐
1. **重构团队结构**——个体生产力经 agent 杠杆放大后，团队拓扑必须演化：更小的
   「agent orchestrator」团队可能取代更大的开发者团队，随之而来的是招聘、晋升与职业
   发展的相应调整

**§8 Conclusion** 收束论证：

- Agent 的涌现是**范式转移而非工具升级**；"AI →Software →Result" → "Agent →Result" 消除
  了静态软件制品作为必要中介——正如 SaaS 消除了 on-premise 安装、云消除了物理基础设施
- 第一性原理重述：传统软件要求人显式编码全部决策逻辑，复杂度随系统规模指数增长而人的
  容量固定；agentic 系统把决策外包给容量随训练算力缩放的 LLM，解耦解算能力与人类认知
  极限——能经济解决的问题种类发生**质变**
- 但仍在早期：EvoClaw 显示孤立任务与持续自主开发之间存在显著差距；当下该做的是
  「ambitious but calibrated investment」——把 agentic engineering 作为主导的
  augmentation 范式拥抱，同时承认完全自主软件工程仍是多年研究挑战
- 收尾判断：Agentic Engineering 是带着自己的概念、工具与职业认同的新兴学科；其从业者
  不是学了新工具的程序员，而是一种新型职业——**intent architects**，指挥成群 AI agent
  达成复杂结果。「The old software engineering is ending; the new one has already begun.」

## 要点归纳

- 组织建议的顺序是渐进路线：先找 agent-ready 任务切入 → 评估先行 → 组织重构放在最后
  （组织结构跟随评估能力成熟）
- 结论与 Abstract 首尾呼应：从「constitutes a fundamental restructuring」到「the old
  software engineering is ending」，立场始终是范式级
- 结尾把职业叙事也升级了：新职业身份（intent architect）而非「更会写代码的程序员」

## 术语 / 概念

- **agent-ready workflow（agent 就绪工作流）** — 判据清晰、范围明确、有测试基础设施
  的任务类型；组织转型的切入点
- **evaluation frameworks（评估框架）** — agent 输出质量的关键杠杆；要测
  robustness / maintainability / business-intent alignment
- **agent orchestrator（agent 编排者）** — 未来团队的最小单位：小团队编排 agent 群
- **intent architect（意图架构师）** — 论文对新一代从业者的最终称呼（收束于结论）

## 原句摘录

> The old software engineering is ending; the new one has already begun.

> The current moment calls for ambitious but calibrated investment: embrace agentic
> engineering as the dominant paradigm for augmentation while recognizing that fully
> autonomous software engineering remains a multi-year research challenge.
