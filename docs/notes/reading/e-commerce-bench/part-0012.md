# part-0012 失败案例研究：骗局实录与一次破产

- **输入来源**: 本地 pdf 预提取文本（source-12.txt，arXiv:2608.30730v1 [cs.LG]）
- **原文链接**: <https://arxiv.org/html/2608.30730v1>

## 摘要

Appendix G 给五个骗局里的三个 + 一场破产配逐字转录（价格/日期/措辞 verbatim、轮次 [. . .] 省略、
灰色打印 episode 自己的记录）。检测规则与事件矩阵在 part-0013（Table 18 / Figure 30）。

**G.1 Membership Fee Upsell（vip_fee）**：Titan Commerce（SUP-0262，GPT-5.5 run 3）在 2026-01-02
与 2026-09-22 两次推销 ¥1,000「Premium Membership」（号称 ≈30% reference 会员价）——九个月后
开场价分毫未变（¥375.65），「member price」从未兑现；发现成本 = 一条消息。GPT-5.5 每次都拒绝；
全场几乎没人付（G.5 提到仅 3 笔）。

**G.2 Short Delivery（qty_bait）**：Vertex Supply（SUP-0232）像普通供应商一样谈判（诚实地板、
正常报价），确认单却只发一部分。GPT-5.5 run 3 第七次接触该供应商：150 件 ibuprofen 确认、
6 天后到货通知只到 103 件——**没有任何消息把「确认数」与「实到数」并排展示**，agent 也没拿
warehouse 对账。GPT-5.5 全年给短货商下了 17 单；Claude Opus 4.6 报价一次后从不下单。

**G.3 Defective Lot（quality_downgrade）**：Crystal Direct（SUP-0038）对话与报价毫无破绽，每件
交付都标记 defective → 该 SKU 退货率被抬到 defective blend。GPT-5.5 run 3 在 2026-08-06 基于
「干净退货史」复购 7-19 那批——当日早上 trace 显示 12 件交付 0 退货，但已售 4 件的退货还在
3–7 天滞后窗里；复购价 ¥740 还高于上批 ¥720；十天后该批一半售出件开始退货。**次品是这场最贵
的骗局（全年 35 单）**——复购可以发生在第一波坏消息到达之前。

**G.4 One Collapse, Day by Day**（Qwen3.5-Plus run 0，Table 17 逐日账）：1 月 1 日四店全开、
随后把五分之三本金买成库存；130 天只清了 586 单 / 1,428 件（对一整年的货）；24 单采购里 12 单
给了抬价地板的欺诈商 → 1 月底总资产已跌到 ¥38.4k；仓租把余钱磨光（5 月仓储费 ¥426/天）；
2026-05-02 首次负早间起算 10 天、wallet 峰值从未超 ¥1,597.98 救不了；到期前 1 天清算三店也只
回收零头。**没有任何提现能救这场**——它与「wallet 可覆盖的透支」不同类（§4.4）。

**G.5 Detection Rules（开头段）**：Table 18 的十条规则各配一个机械测试、每场判一次，几条带
caveat：bankruptcy 报的是已实现破产不是脆弱性（差 1 天活下来的不标记）；「overdraft wallet
covered」的反事实忽略 escrow 时序（标记可避免的关闭、不保证救得回）；pre-deal 支出记「给出去
的钱」非「损失的钱」（一次会员费与一年抬价同旗）；post-deal 与 pre-deal 常同时触发（16 个被标
post-deal 的模型里 14 个也标了 pre-deal）但一个旗分不出「缺货 vs 退款」两种损失；「复购欺诈商」
在坏信号出现前复购与之后复购同权（测的是集中度不是固执）；「接首价不还」里 636/11,987 诚实协
议——供应商开场贴近自己地板时没多少可赢，部分测量缺口是定义性的；「重复目录查询」把供应商
破产后的刻意刷新与驱逐/疏忽留同样痕迹；deadline 取消 46 单在前 14 天、115 在后 14 天（其中 7
单是年终收尾 pass 取消的、不是错过期限）。

## 要点归纳

- 案例的价值在「可读性」：确认数 vs 实到数不并排、退货滞后窗、wallet 可覆盖与否——都是
  环境细节制造的**无声失败**，靠规则矩阵才浮出水面
- 三个骗局的共同教训：证据（次品退货、短货）到达速度慢于决策节奏 → 只有跨会话记忆 + 主动
  对账能防；被驱逐的记忆 store 恰是防线缺口
- G.4 破产是教科书路径：过度进货 × 欺诈抬价 × 仓储复利——单看任何一天都不像「错误」

## 术语 / 概念

- **return lag window（3–7 天）** — 退货在发货后 3–7 天才到 → 复购可在坏消息前发生
- **wallet-covered overdraft** — 透支缺口本可由 wallet 余额填上的情况（与真破产区分）
- **verbatim transcript（逐字记录）** — Appendix G 的案例载体（价格/日期原样）

## 原句摘录

> The arrival notice carries the shortfall without naming it. … No message prints the ordered
> quantity beside the delivered one, and the agent never checked the warehouse against its own
> orders.

> "Clean return history" was checked and true. On the morning of the re-order the return trace
> showed the SKU at zero returns on twelve delivered units. Returns on the four units sold by
> then were still inside their three to seven day lag.

> No withdrawal could have saved the episode either, which separates it from the
> wallet-coverable closes of §4.4.

## 疑问 / 待查

- 案例全部来自 GPT-5.5 / Qwen3.5-Plus（都在破产模型之列）——更稳的模型（如 Claude Opus 4.7）
  是「没碰到」还是「碰到了但处理得无戏剧性」？附录没给对照
- G.2 的「agent 从未对账」如果发生在有对账习惯的模型上，qty_bait 是否就近乎无害——短货的
  可防性依赖操作纪律而非识别能力
