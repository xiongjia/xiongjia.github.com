# part-0006 工具集与 agent harness：18 工具与上下文管理

## 摘要

**Table 3：18-tool action space**（7 组，分钟成本 + 环境效果）：

- 市场调研：market_search（30，三级披露：店型/类目/单类目销售带，退货与 margin 给定性标签）、
  supplier_search（10，名字/联系方式/类目，无价格/评级/诚实信号）
- 店铺运营：trace_return_sources（10，把混合库存归因到送货供应商）、open_store（60，¥500 开店，
  ≤4）、close_store（30，关店，货回仓或 10% 残值清算）、check_store_status（10，昨日营收/退货/
  运费/单 SKU 速度）、set_prices（10，改写货架价，次日触发生效）、join_promotion（10，以 0.05–
  0.50 折扣报名促销）
- 库存：list_products（10，可售 SKU + reference 价）、check_warehouse（10，仓内数量 + 实付价）、
  publish_to_store（20，上架，仓储照计）、return_to_warehouse（15，下架回池）、ship_orders（20，
  扣运费、净额进 9 天 escrow、按所选速度种退货）
- 财务：check_balance（10，四个桶 + 结算日）、withdraw（10，唯一 wallet→bank 通道）
- 谈判：chatbox（30，一条自由文本可发给 1 到多家，fenced negotiate 块路由进内核）
- 记忆：operate_memory（10，20 条窗口外条目增删改查）
- 时间：wait_for_next_day（0，跳次日 08:00、放弃当日剩余分钟、触发日管线）

**A.1 The Interface Contract**：模型只见工具 schema 与回复——所有通知都塞在回复里。结构化结果
返回 JSON、纯文本原样；额外通知放 JSON 内部（关闭括号前，保证仍可 parse）；按日通知挂在跳日
结果上（避免算到无关早先调用头上）。早间 pass 算了 17 个字段只报 3 个给 agent（日期、day 索引、
新闻 feed）——90 场里该通道共运 8,301 条、其中 6,722 条是每日一条的到货聚合。Listing 1 给两
条真实工具消息（一条带日通知、一条带破产前余额警告），都带窗口外的 token 计量条
（`<system_warning>Token usage: …</system_warning>`）。

**A.2 Loop Control and Context Editing**：token 计数用本地 tokenizer（覆盖文本 + 工具调用 +
推理轨迹；加密 reasoning 的 opaque artifact 与窗口外 schema 不计入）。system prompt 直接告诉
模型 120k 阈值 / 60k 释放地板 / 两个受保护组。驱逐 pass 六步：① 未清消息求和，低于上限只发
usage 字符串；② 从第三条消息起找组（assistant 带工具调用开场、到其连续工具结果末尾），system
与首个 user turn 永久豁免；③ 最新两组豁免——只剩 ≤2 组时什么都不清（少数超大组的窗口可长期
悬在上限上）；④ 释放目标 = max(地板, 超限部分)；⑤ 从最旧可清组开始标记、累计到达标；⑥ 重建
请求、整体跳过已清条目。两类消息永远不可驱逐：纯文本 assistant turn 与 idle warning（它们不
开组也不在组内）——整组清除是保持 transcript 有效的方式（任何 provider 协议都拒绝工具结果
脱离调用）。

## 要点归纳

- 分钟制让「信息获取」与「行动」共享同一时钟预算——查余额 10 分钟与发货 20 分钟同池竞争，
  这使查询成本成为策略变量而非固定开销
- 驱逐粒度 = 组（一次回复 + 其全部工具结果），约 50 组/窗口；被逐文本无痕消失 → 记忆 store
  是唯一抗驱逐通道（但读回即重新可驱逐，形成 token 税）
- 接口契约对「通知归属」很讲究（day-scoped notices 挂跳日结果），避免误导归因——评测工程
  细节决定行为信号质量

## 术语 / 概念

- **fenced negotiate block** — chatbox 自由文本里 ```` ```negotiate ```` 包裹的 JSON 经济动作
  （offer/accept/reject），文本其余部分只是对话
- **context eviction（上下文驱逐）** — 120k 触发、60k 释放、整组从旧到新
- **token gauge** — 回复末尾的 `<system_warning>` token 用量条（在 JSON 之外）
- **turn budget（4,000 回合）/ three idle turns** — 回合制循环的两个终止条件

## 原句摘录

> The agent is told the policy verbatim, thresholds included, so preserving what matters in its
> memory is a choice it can make.

> Reading the store back is cheap in minutes yet expensive in tokens, since returned entries
> re-enter the context and become evictable like everything else.

## 疑问 / 待查

- 把驱逐策略逐字告知模型 = 把「harness 顺应」变成能力变量：会主动写 memory 的模型（如 Claude
  Opus 4.8 用 4.7% 调用）与不会的（Qwen3.5-Plus 0%）差距被算进能力画像是否公平，值得讨论
- Listing 1 展示了真实 token 计量与余额提醒的格式，可作复现自己 runner 的参考
