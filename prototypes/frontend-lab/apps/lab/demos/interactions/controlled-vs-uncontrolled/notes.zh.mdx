---
title: 受控与非受控
summary: 两个输入框、一个提交计数器 —— 把“持有值”的代价测出来，而不是争论出来。
---

## 证明了什么

受控输入每次按键都会重渲染持有者；非受控输入直到有人取值才重渲染。上面的提交计数器就是测量结果，
不是渲染次数的估算。

## 决策

- **计数器放在渲染期间自增的 ref 里。** 这类插桩是渲染期改 ref 唯一合理的场景：数字本身就是目的，
  挪到 `useEffect` 里会变成“事后计数”，还平白多一次渲染。
- **“读取值”才是非受控的诚实 API。** `ref.current.value` 让你拿到值而不持有它；`form.elements`
  也行。读取本身必须触发一次渲染，所以“最近读取”那一行才会变化。
- **不引入受控状态库。** 对示例来说，`useState` 是能证明结论的最小方案；一个 store 反而会掩盖这
  页真正想讲的提交成本。
- **两个输入框都保留焦点环。** 非受控不是“更省的 UI”，而是同一套 UI 换了个持有者。

## 怎么选

| 需求                                      | 受控   | 非受控                     |
| ----------------------------------------- | ------ | -------------------------- |
| 输入过程中需要派生 UI（计数、校验、禁用） | 是     | 需要额外接线               |
| 程序化重置 / 格式化                       | 是     | 换 `key` 或 `form.reset()` |
| 大表单，只在提交时读一次                  | 浪费   | 是                         |
| 文件输入                                  | 不可能 | 是（文件归 DOM 所有）      |
