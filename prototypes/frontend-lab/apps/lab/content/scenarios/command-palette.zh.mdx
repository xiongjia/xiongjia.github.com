## 场景

每个应用迟早会长出这一个输入框：什么都能干。B16 把它做成一个包
（`@frontend-lab/command-palette`），并证明真正难的部分——不是过滤，而是焦点。

两个使用方共享同一份实现：

- **实验室外壳**把它挂在顶栏，快捷键 `Mod+K`；命令由内容索引、示例索引和显示偏好生成。新增一个
  页面，就新增一条命令。
- **示例**用同一个组件但自带命令集和快捷键（`Mod+J`，避免与外壳的处理器抢同一个键）。

## 命令面板必须做对的几件事

### 1. 它是一个对话框

`role="dialog"`、`aria-modal="true"`、可访问名称、Esc 关闭、背景点击关闭（且仅当点击目标就是背景
本身）。打开时锁定页面滚动，关闭时在同一个 cleanup 里解锁并归还焦点。

### 2. 它是 combobox，不是「搜索框 + 列表」

整个会话期间焦点都留在输入框里。当前选项通过 `aria-activedescendant` + `aria-selected` 表达，而
不是把焦点移到选项上。这正是「一边输入一边用方向键」能成立的原因，也是命令面板与筛选列表的区别。

几个容易做错的地方：

- `aria-activedescendant` 必须始终指向存在的选项 id。活动下标被夹在当前匹配数量内，id 由扁平下标
  推导，所以输入过滤不可能留下悬空引用。
- 方向键循环、Home/End 跳到首尾，活动项用 `scrollIntoView({ block: 'nearest' })` 滚入视口——绝不
  滚动整页。
- Tab 被吞掉。模态对话框让 Tab 跑到背后的页面里，那是焦点陷阱的 bug，不是特性。

### 3. 关闭后焦点归位

打开时记住 `document.activeElement`，关闭时重新聚焦它。这是最常被漏掉的一步：没有它，用户关掉面板
后键盘路径就等于从头开始。示例里的触发按钮就是证据——关掉面板再按 Enter，面板会再次打开。

### 4. 排序必须可解释

标题与关键词处于不同的分数带：

| 匹配类型   | 例子                           | 分数带                       |
| ---------- | ------------------------------ | ---------------------------- |
| 完全相同   | 「设置」对 `settings`          | 标题                         |
| 前缀       | `Settings panel` 对 `settings` | 标题                         |
| 词首       | `Open settings` 对 `set`       | 标题                         |
| 中间子串   | `Preset` 对 `set`              | 标题                         |
| 子序列     | `Settings` 对 `stg`            | 标题                         |
| 关键词命中 | `preferences` 对 `settings`    | 关键词——永远低于任何标题命中 |

任何标题命中都排在关键词命中之前。同分保持调用方顺序，于是「最近使用」不用第二次排序就能占据前几个
位置。命中的字符以合并后的区间返回，界面在真实标题上渲染 `<mark>`，而不是另造一份高亮字符串。

### 5. 最近使用是一个独立的小功能

id 存在 `localStorage`（有上限、读取时校验）。查询为空时，最近使用的命令先出现并带自己的分组标题；
一旦开始输入，排序接管，最近分组消失。两者只在一种状态下共存，因此不会互相打架。

## API

```tsx
const commands: PaletteCommand[] = [
  { id: 'settings', title: 'Open settings', group: 'Navigation', keywords: 'preferences', run },
]

<CommandPalette
  open={open}
  onClose={close}
  commands={commands}
  label="命令面板"
  recentLabel="最近使用"
  storageKey="app:palette-recent"
  hint="↑↓ 移动 · Enter 执行 · Esc 关闭"
/>
```

`run` 由调用方提供；面板负责调用、关闭并记录 id。纯匹配器单独导出
（`@frontend-lab/command-palette/match`），所以排序规则由 `node:test` 覆盖，而不是靠浏览器。

## 验证了什么

示例与外壳集成都是通过 DOM 断言检查的，不是截图：对话框角色与名称、打开后焦点在输入框、Tab 不会逃出、
`aria-activedescendant` 跟随方向键、过滤生效、Enter 执行并关闭、焦点回到触发按钮、重新打开时出现
「最近使用」，以及 `Mod+K` 能把外壳导航到某个示例。

## 没做的

- **不做嵌套命令与参数输入。** 会要求输入的命令是另一种交互模型（也是另一套 ARIA 模式）。
- **不做虚拟列表。** 实验室的命令不到 60 条；为了性能引入虚拟列表，反而会掩盖这一批要证明的焦点行为。
- **不拿语料调模糊评分。** 规则刻意保持可解释——没人能预测排序的面板，哪怕分数「更优」，用起来也是随机的。
