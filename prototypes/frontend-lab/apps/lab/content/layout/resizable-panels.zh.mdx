## 四条要求

可拖拽布局用鼠标做出来很容易「感觉对了」，也很容易变得完全没法用键盘。`packages/panels` 按这个顺序
解决四件事：

1. **拖拽跟随指针** —— 包括指针离开那 6px 分隔条之后。
2. **尺寸是百分比**并且经过夹取，任何交互都不可能把面板压到 0 宽。
3. **键盘能做指针能做的一切** —— 独立调整、跳到边界、复位。
4. **选择能穿过刷新**，且不会先闪一下默认布局。

## 指针捕获

```ts
separator.setPointerCapture(event.pointerId)
```

不做捕获时，快速拖动会让指针离开分隔条，浏览器把 `pointermove` 发给指针下面的元素，拖拽中途断掉。
捕获把事件流固定在分隔条上，顺带省掉了给 `<body>` 加 `user-select: none` 的老做法：被捕获的指针
不会选中文字。

位移换算用的是在 `pointerdown` 时测量一次的容器尺寸：

```ts
size = startSize + (deltaPx / containerPx) * 100
```

每次移动都重新测量也能工作，但会在热路径上读布局，而这个值在一次拖拽中不会变。

## 不闪的持久化

`useSplitSize` 在**首次渲染**时就读 `localStorage`（`useState` 的惰性初始化），所以第一帧已经是存下的
分割比例——和 `index.html` 里主题启动脚本是同一个道理，只是省掉了内联脚本，因为面板是 React 渲染的，
不是文档本身。

非法值直接夹取，不报错：`localStorage` 里的内容不是需要跟它争论的用户输入。

## 分隔条就是控件

| 要求   | 实现                                                          |
| ------ | ------------------------------------------------------------- |
| 可聚焦 | `tabIndex={0}`、`role="separator"`                            |
| 可播报 | `aria-valuenow/min/max`、`aria-orientation`、`aria-valuetext` |
| 可调整 | 方向键 ±4%、PageUp/PageDown ±12%、Home/End、`Enter` 复位      |
| 有关系 | `aria-controls` 指向两个面板，两个面板都有名字                |

一个只挂了 `onPointerDown` 的 `div` 实现了第一行，其余一条都没有。

## 面板就是容器

两个面板都带 `@container`，这是 B8 的收益：面板里的卡片跟随**分割线**重排，而不是跟随窗口。这也是
可拖拽布局不只是 flexbox 技巧的原因——内容必须能回答新宽度。

## 刻意不做的事

- 拖拽计算不用容器上的 `ResizeObserver`：百分比让它没有必要。
- 不用状态库：每个分割一个数字，不值得上 store。B11 对「多个组件共享的状态」做了相反的判断。
- 不做折叠面板，也不做像素级的单面板 `min`/`max`：那是 B13 的 IDE 布局才需要的具体需求。
